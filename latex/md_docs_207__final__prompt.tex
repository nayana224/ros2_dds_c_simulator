실제 ROS2 라이브러리나 하드웨어는 사용하지 않고, ROS2의 Pub/\+Sub와 DDS 메시지 전달 개념을 C언어 자료구조로 단순화하여 구현한다.

\doxylink{struct_node}{Node}, \doxylink{struct_topic}{Topic}, \doxylink{struct_publisher}{Publisher}, Subscriber는 연결 리스트로 관리하고, Message는 \doxylink{struct_topic}{Topic} 내부 priority queue로 처리한다. 전체 publish/subscribe 관계는 그래프 형태로 출력하며, 특정 Node에서 다른 Node까지 메시지 전달 경로가 존재하는지 BFS로 탐색한다.

프로그램은 하나의 로컬 실행 파일로 동작하며, socket, DDS, RTPS, 외부 네트워크 라이브러리는 사용하지 않는다. CLI는 명령어 기반으로 구성하여 ROS2 명령어를 사용하는 느낌을 단순하게 모방한다.\hypertarget{md_docs_207__final__prompt_autotoc_md67}{}\doxysection{\texorpdfstring{2. 구현 요구사항}{2. 구현 요구사항}}\label{md_docs_207__final__prompt_autotoc_md67}

\hypertarget{md_docs_207__final__prompt_autotoc_md69}{}\doxysection{\texorpdfstring{4. 핵심 설계 기준}{4. 핵심 설계 기준}}\label{md_docs_207__final__prompt_autotoc_md69}

\begin{DoxyItemize}
\item C언어만 사용한다.
\item 실제 ROS2, DDS, RTPS, socket, 외부 네트워크 라이브러리를 사용하지 않는다.
\item 자료구조 수업 프로젝트 수준에 맞게 단순하고 설명 가능한 구조로 구현한다.
\item 동적 할당한 메모리는 {\ttfamily \doxylink{simulator_8h_ac0e87a2b6604fe4e9d9ffe591ab04a71}{simulator\+\_\+destroy()}} 또는 호출자가 {\ttfamily free()}로 해제한다.
\item 각 주요 기능은 연결 리스트, priority queue, graph, BFS 중 어떤 자료구조를 사용하는지 설명 가능해야 한다.
